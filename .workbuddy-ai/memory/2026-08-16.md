## 修正：server getClientAbortSignal 誤 abort（根因 This operation was aborted）
- 使用者自行定位：`batch-quark-search.mjs` 打本地 `http://localhost:4000/api/search` 時收到 `This operation was aborted`。
- 根因在 **panhub 後端** `server/api/search.get.ts` 與 `search.post.ts` 的 `getClientAbortSignal()`：監聽 `req.on("close")` 且條件 `req.destroyed || req.writableEnded===false && req.readableEnded`。`req.destroyed` 在請求正常接收完即為 true，故**每一次正常請求都被誤 abort**，server 端 search 被中斷 → 客戶端 fetch 收 AbortError。
- 為什麼瀏覽器（官網）沒事：官網打的是遠端線上伺服器，不走本機 Nuxt dev server，不受此 bug 影響；本機 `npm run dev` 才踩到。
- 修法（兩檔案一致）：改用 `res.on("close")` + `if (!res.writableEnded) controller.abort()`——只在「回應尚未送出（客戶端提前斷線）」時才中止，正常完成（writableEnded=true）絕不中止。已備份 `search.get.ts.bak`。
- 驗證：寫 `_verify_abortsignal.mjs` 模擬 `res` EventEmitter，確認 writableEnded=true→不 abort、false→abort，VERIFY PASS（驗證檔已刪）。無法在 sandbox 實跑真後端（需使用者重啟 `npm run dev` 才生效；Nitro server route 改動建議重啟）。
- 關鍵提醒（使用者曾踩坑）：PowerShell 設環境變數必須寫在 `node` 之前（`$env:PLUGIN_TIMEOUT_MS="60000"` 另起一行），否則等於沒設、沿用預設 15000→client 在 20000ms 自行 abort。慢搜 `src=all` 需把 `PLUGIN_TIMEOUT_MS` 調大（如 60000~120000）。
- 附帶發現（與本機後端無關，備查）：live 站 `panhub.shenzjd.com/api/search?src=all` 有**反向代理 60s 硬上限**，多插件併搜會 504；官網前端是對 8 個插件各別 `src=plugin&plugins=X` 並行再合併，故不受限。本機後端無此限制，修好 abort bug 後 `src=all` 可正常跑。

## 修正：SEARCH_SRC 預設改 "plugin" 跳過 TG（第二個 root cause）
